## V1 — Clasificador

### Implementado
- CLI `cmd/classify`:
  - modo dataset (`-in dataset`) con worker pool, timeout por imagen y métricas.
  - modo ZIP (`-zip fotos.zip`) con salida `aceptadas.zip` / `descartadas.zip`.
  - salida JSON (`out/informe.json`) + resumen en consola + lista de falsos negativos.
  - códigos de salida: 0 ok, 1 error, 2 recall < `-min-recall`.
- Proveedores:
  - `jev`: POST `/api/v1/decisions` con imagen inline en `state.image` (experimental).
  - `openai`: visión vía `/chat/completions` con `response_format=json_object`.
  - `chain`: Jev → OpenAI con fallback y circuit breaker (3 fallos consecutivos).
  - `mock`: determinista por hash, para smoke tests sin API.
- `internal/imageprep`: decodifica jpg/png/webp/gif, reescala (256–1568) y reencoda JPEG; rechaza panorámicas incompatibles.
- `internal/zipset`: lectura/escritura de ZIP, omite `__MACOSX`, `.DS_Store` y no-imágenes.
- `internal/evaluate`: matriz TP/TN/FP/FN, accuracy, precision, recall, F1, specificity; los errores cuentan como descarte.
- `internal/config` + `internal/envfile`: configuración por entorno y carga de `.env` sin sobreescribir.
- Servidor base `cmd/photo-clean`: `/healthz` y página placeholder (V2 pendiente).
- Infra dev: `.env`, `.env.example`, `.dockerignore`, `Dockerfile.dev`, `docker-compose.yml` (servicios `web` y `classify` perfil `tools`), `Makefile`.

### Decisiones e incidencias
- `jevai.org` es un modelo de decisión **textual**: JSON con cuerpo máximo de 32 KiB y sin multipart/`assets`; no hay endpoint de visión documentado. El adaptador recorta la imagen y la manda como data URL, pero el resultado no es fiable.
- TypeSafe (`api.typesafe.ai`) sí soporta imágenes (Jev 1.14, multipart + `assets`), pero la clave `jev_…` no autentica allí (401).
- `OPENAI_API_KEY` queda vacía: falta clave para ejecutar el test real y la comparativa Jev vs OpenAI.
- Dataset real pendiente de añadir en `dataset/motivo` y `dataset/paisaje`.

## Dataset de prueba desde Hugging Face

### Fuente
- `nlphuji/mscoco_2014_5k_test_image_text_retrieval` (COCO 2014 test, 5.000 imágenes, captions).
- Etiquetado heurístico: caption menciona persona/animal → `motivo`; si no → `paisaje`.
- Descarga vía datasets-server de HF (sin bajar el dataset completo): 150 + 150 imágenes, 16 MB.
- Script `scripts/fetch_dataset.py` (reanudable, deja `dataset/manifest.tsv`).
- Alternativas documentadas: LHQ 256, Places365 y Animals-10.

### Primera medición (decisions)
- 300 imágenes, 53,6 s, 0 errores de clasificación.
- TP=144 · TN=128 · FP=22 · FN=6
- Accuracy=0.907 · Precision=0.868 · Recall=0.960 · F1=0.911 · Specificity=0.853
- **Recall ≥ 0.95: superado.**

### Revisión de errores
- Los 6 FN son ruido de etiqueta o casos que el prompt excluye a propósito: figurinas de caballos, un cuadro, una foto de una foto, muñecos y un disfraz.
- Muestreo de FP: persona en segundo plano y un cisne, no mencionados en el caption.
- Conclusión: el modelo clasifica bien; el límite actual es la etiqueta automática, no el clasificador.
